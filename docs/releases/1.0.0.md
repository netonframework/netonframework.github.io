# Neton Framework 1.0.0

> Release preparation, not yet published. Availability will be confirmed after production
> publication and independent consumption from public Maven Central.

Neton Framework is a Kotlin/Native server application framework with compile-time wiring,
routing, managed lifecycle and backend infrastructure. AI-native development uses its versioned
specifications and development skill to build and verify services; it does not require runtime AI.

Neton Application is a separate application/module ecosystem built on Framework. Administration,
business identities and product modules are not Framework contracts. The public
[neton-app](https://github.com/netonframework/neton-app) is a generic Framework starter.

## Capabilities and boundaries

- Controllers, routing, validation, middleware and consistent error handling.
- KSP-generated registration and mappings, deterministic startup and owned resource shutdown.
- Typed database access, transactions and explicit migrations; authentication, authorization and JWT.
- Cache, Redis, jobs, structured logging, domain events, local and S3-compatible storage.
- Stable business WebSocket APIs in `neton.websocket`; the opt-in engine SPI remains experimental.
- Default HTTP server/client using the project's own HTTP, IO and TLS libraries, with one OpenSSL 4
  wrapper shared by HTTP/TLS, Security and Storage.

`neton-ai` is independently versioned and released, outside the Framework BOM; its APIs remain
experimental. Ktor, Hyper4k and Geario4k adapters are external optional compatibility/comparison
projects, not the default stack or core release gates.

Public APIs in the compiled ABI baseline are stable except explicitly internal/experimental APIs.
KSP implementation classes are not application extension points.

## Versions and platform scope

Kotlin stays at **2.4.20**, KSP at **2.3.12**. This candidate updates **sqlx4k 1.16.0 → 1.17.0**
and **kotlinx-serialization 1.11.0 → 1.12.0**. New candidate gates must pass after these changes;
old green runs do not certify them. Arbitrary compiler-version KLIB compatibility is not promised.

Full native runtime gates cover macOS ARM64, Linux x64 and Windows x64. Linux ARM64 has a separate
actual KSP execution gate, not full runtime certification. macOS x64 library compilation is not
runtime acceptance; the database module has no macOS x64 artifact. Default database publications use
PostgreSQL; MySQL/SQLite API-variant checks do not imply published interchangeable drivers.

## Beta migration

- Align Framework and KSP dependencies. The entry module BOM aligns Framework modules, not AI/adapters.
- Rename `neton.ws` to `neton.websocket`. The annotation is
  `neton.websocket.annotations.WebSocket`; configuration is `neton.websocket.config.WebSocketConfig`.
- Use request-bound `SecurityContext(httpContext)` or `@CurrentUser`, not global identity.
- Do not access SQLx adapter internals from business code. Explicit opt-in applies to experimental APIs.
- Remove old BOM/version constraints when moving to independent AI.
- Security preserves stored PBKDF2 hashes and SecretBox layouts through regression tests; do not
  reintroduce an OpenSSL 3 provider.
- Recompile consumers. Pre-1.0 changes do not promise beta binary compatibility.

Use the [Framework skill](https://github.com/netonframework/netonframework.github.io/tree/main/skills/neton-development)

## Release verification

The gates require compiled ABI, consumer compilation, incremental KSP, real PostgreSQL/Redis,
native tests, release migration, two healthy start/stop cycles, closed ports and zero database
connections. The pinned public starter consumes the same candidate on three runtime platforms.
Production signatures and public Central consumption are separate from test-key candidate rehearsal.

See the [release contract](https://github.com/netonframework/netonframework.github.io/blob/main/docs/zh-hans/spec/release-freeze-contract.md) and
[release gates](https://github.com/netonframework/netonframework.github.io/blob/main/docs/zh-hans/spec/release-gate.md). No performance or additional platform certification
is implied by this release note.
