# 1.2.0 实施基线（非发布验收）

对应 [r26 路线图](../roadmap-1.2.0.md) §12。检查的框架基线为 `f959118`。下表路径相对于框架仓库；“已有”表示能定位复用点，不表示通过新契约。不要把本表当作发布许可。

| 工作项 | 已有基础 / 检查入口 | 尚不能据此证明 |
|---|---|---|
| N12-01 平台与依赖 | `gradle/libs.versions.toml`、`settings.gradle.kts`、`.github/workflows/backend-ci.yml`；r26 §2.1 记录历史版本和验证边界 | CI 声明不等于候选提交实跑；本地 composite 与已发布依赖必须分别核对 |
| N12-02 编译期架构 | KSP 的 `ApplicationRegistryProcessor.kt` 将模块 id 解析为入口；`tools/ci/ksp_incremental_gate.py` 检查增量构建 | registry 不是含全部依赖边、来源、同一构建摘要的应用清单 |
| N12-03 OpenAPI | `ControllerProcessor.kt` 及 `ControllerProcessorDiagnosticsTest.kt` 已检查部分路由和参数声明 | 不等于按最终装配导出 OpenAPI；需 OA-01～28 及真实消费者往返 |
| N12-04 期限与生命周期 | `LifecycleContractTest.kt`、`ManagedWebSocketSession.kt`、`NetonStreamHttpClient.kt` 的请求超时 | HTTP 凭据撤销不等于旧 WS 停止交付；需要独立的 WS-AUTH 矩阵与跨调用预算验证 |

| N12-07 Durable | `DbContext.transaction`、`DomainEventBus.kt`、`DomainEventBusTest.kt` | 没有用本地事务测试替代跨进程恢复；需 §8 的原子存储、确认、迁移故障验收 |

| N12-09 真实注册中心 | 基于 N12-06，按 §11.5 的发现边界验收 | 静态地址或 DNS 不能替代租约、权限、滚动退出实测 |
| N12-10 Saga | 可复用数据库、事件、jobs；`settings.gradle.kts` 未装配 neton-durable / neton-saga | 未验证 DC-01～54、三服务不变量和跨版本迁移 |
| N12-11 CQRS | 已有事件分发和持久化端口 | 未验证可重建投影在重复和乱序输入下的读写一致性 |
| N12-12 测试设施 | `ScriptedHttpClient.kt`、`tools/ci/verify-integration-report.py`；Application 有临时 PostgreSQL / Redis 的真实接口脚本 | 不等于全套多实例故障、进程中止与恢复夹具 |
| N12-13 网关调研 | 按 §10 与现有代理比较 | 这是调研交付；不以新建网关模块为完成标志 |
| N12-14 外部配置源 | 可选 Consul KV，使用既有配置覆盖规则；`tools/ci/external_config_contract.py` 驱动两个原生 Neton 进程 | 不等于 Consul 服务注册适配、Nacos、TLS 互通验收或 1.2.0 整版验收 |

**平台口径：** macOS ARM64 的本机执行、Linux x64 / ARM64 和 Windows runner 的执行、跨编译与单纯依赖解析分别记录。候选报告应绑定提交、目标、依赖来源、实际执行的用例与跳过项。没有对应运行报告的格子保持未验证。
