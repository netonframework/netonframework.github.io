# Neton Framework 1.0.0

> 2026 年 10 月 29 日发布，1.0.0 已可从 Maven Central 获取。
> 发布后的公开消费结果持续记录于[验收记录](https://github.com/netonframework/netonframework.github.io/blob/main/docs/zh-hans/spec/release-evidence/2026-10-29-stable-release.md)。

Neton Framework 是 Kotlin/Native 服务端应用框架，提供编译期装配、路由、生命周期及后端
基础设施。AI 原生开发是通过版本化规范和开发 skill 编写、验证服务，不要求应用依赖运行时 AI。

Neton Application 是 Framework 之上的独立应用与模块生态，系统管理、业务身份和产品模块
不是 Framework 契约。公开 [neton-app](https://github.com/netonframework/neton-app) 是通用框架模板。

## 能力与边界

- Controller、路由、验证、中间件、统一错误处理。
- KSP 注册与映射生成，确定的启动过程和有归属的资源关闭。
- 类型化数据访问、事务、显式迁移；认证授权及 JWT。
- 缓存、Redis、任务、结构化日志、领域事件、本地及 S3 兼容存储。
- 稳定的 `neton.websocket` 业务 API；要求 opt-in 的引擎 SPI 仍为实验性。
- 默认 HTTP 服务端和客户端使用自有 HTTP、IO、TLS 库；HTTP/TLS、Security、Storage
  统一使用自有 OpenSSL 4 封装。

`neton-ai` 独立版本、独立发布，不进入 Framework BOM，其 API 仍为实验性。
Ktor、Hyper4k、Geario4k 是外部可选兼容/对比适配器，不是默认栈或核心发布门禁。

编译 ABI 基线中的公共 API 默认稳定，显式内部/实验性 API 除外。
KSP 实现类不是应用扩展入口。

## 版本与平台范围

Kotlin 保持 **2.4.20**，KSP 保持 **2.3.12**。本次升级 **sqlx4k 1.16.0 → 1.17.0**、
**kotlinx-serialization 1.11.0 → 1.12.0**。升级后正式源码的 19 项发布门禁已全部通过，
没有沿用旧候选的绿色结果。不承诺跨任意编译器版本的 KLIB 兼容。

完整原生运行门禁覆盖 macOS ARM64、Linux x64、Windows x64。Linux ARM64 另有 KSP 实际
执行门禁，不等于完整运行认证。macOS x64 库编译不等于运行验收，数据库模块没有 macOS x64
制品。默认数据库制品使用 PostgreSQL；MySQL/SQLite API 变体检查不等于已发布可切换驱动。

## Beta 迁移

- Framework 和 KSP 依赖版本必须一致；入口 BOM 对齐框架模块，不对齐 AI/适配器。
- 将 `neton.ws` 改为 `neton.websocket`。注解为
  `neton.websocket.annotations.WebSocket`，配置为 `neton.websocket.config.WebSocketConfig`。
- 使用请求绑定的 `SecurityContext(httpContext)` 或 `@CurrentUser`，不使用全局身份。
- 业务不得访问 SQLx 适配器内部实现；实验 API 需要显式 opt-in。
- 采用独立 AI 时移除旧 BOM/版本约束。
- Security 通过回归保护已有 PBKDF2 哈希与 SecretBox 布局；不得重新引入 OpenSSL 3 provider。
- 消费者需要重新编译；1.0 前调整不承诺 Beta 二进制兼容。

依赖方式：

```kotlin
implementation("com.netonstream:neton:1.0.0")
implementation("com.netonstream:neton-security")
implementation("com.netonstream:neton-database")
```

结合匹配规范和 [Framework skill](https://github.com/netonframework/netonframework.github.io/tree/main/skills/neton-development)
开发。Skill 提供执行指引，不替代编译与验收。

## 发布验收

门禁要求编译 ABI、消费者编译、KSP 增量、真实 PostgreSQL/Redis、原生测试、release 迁移、
两轮健康启停、端口关闭和数据库连接归零。固定公开模板在三个运行平台消费同一候选。
生产签名及公开 Central 消费独立于测试密钥候选演练。

详见[冻结契约](https://github.com/netonframework/netonframework.github.io/blob/main/docs/zh-hans/spec/release-freeze-contract.md)及[发布门禁](https://github.com/netonframework/netonframework.github.io/blob/main/docs/zh-hans/spec/release-gate.md)。
本说明不暗示额外性能或平台认证。
