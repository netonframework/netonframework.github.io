# 安全策略（草案）

> 状态：草案。报告渠道与响应时限需由维护者确定后填写；定稿前不在各仓库发布 `SECURITY.md`。

## 范围

`com.netonstream` 下的 io、http、websocket、quic、http3、tls（含 tls-http、tls-websocket）、msgtrans（含 msgtrans-quic、msgtrans-websocket）。
OpenSSL 本身的漏洞按 OpenSSL 项目的流程报告；本栈负责在其安全版本发布后跟进 `openssl` 产物与依赖它的库。

典型的安全问题：解析器的越界、整数溢出与拒绝服务；请求走私与解析分歧；资源上限失效（内存、流数、解压输出、握手）；证书或主机名
验证错误；0-RTT 重放；原生内存的生命周期错误（释放后使用、重复释放）。

## 报告

- 渠道：**待维护者确定**（不要在公开 issue 中报告未修复的漏洞）。
- 请提供：受影响的库与版本、平台与驱动、复现步骤或输入、影响评估。

## 处理流程

1. 确认收到 —— 时限：**待定**。
2. 复现与评估严重程度。
3. 修复：以回归测试锁定（去掉修复即失败）；可依 [工程标准 §11](./standards.md#_11-例外) 在其他发版门槛未满足时先发布。
4. 发布修复版本，在发布记录与各库 CHANGELOG 中说明影响范围与升级方式。
5. 公开披露 —— 时限：**待定**（与报告人协商）。

## 支持的版本

1.0 之前只为最新的次版本线提供安全修复。
