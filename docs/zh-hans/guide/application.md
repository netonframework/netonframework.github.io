# Neton Framework 与 Neton Application

Neton 面向服务端应用开发：构建 API、后端服务和业务系统。原生网络能力为这一目标提供底座；开发普通业务功能不需要自行组装协议栈。

## 两个层次，不同职责

| | Neton Framework | Neton Application |
| --- | --- | --- |
| 定位 | 通用服务端应用框架 | 基于框架的模块化业务应用底座 |
| 提供 | 路由、依赖注入、配置、数据访问、事务与安全扩展点 | 可复用应用模块、产品装配及配套的管理前端模块 |
| 负责 | 编程模型、组件生命周期与基础设施抽象 | 业务身份、权限、应用流程与模块对接 |
| 适合场景 | 使用自己的领域模型开发后端服务 | 复用业务能力并扩展应用发行版 |

Application 使用 Framework，并不替代它。Framework 不要求引入 Application，也不强制采用它的业务约定。

## 组装业务应用

Application 将产品装配与可复用模块分开。例如，system 负责管理员身份与权限，account 负责终端用户身份，infra 提供文件处理等共享基础能力。产品选择兼容的模块，补充自己的业务逻辑和展示方式。

扩展通过文档化契约、配置和注册机制完成。优先复用已有能力，不跨模块读表，也不在通用模块中增加产品专属分支。模块化底座不意味着无需开发就能得到任意产品。

模块可用性、媒体处理和内容平台能力随版本变化。设计规范不等于已发布实现；应核对所选模块的源码、文档与验收记录。

## 网络能力放在哪里

[技术架构与网络生态](/zh-hans/ecosystem/)介绍底层 I/O 与协议库，它们也可以独立使用。服务端业务代码通常通过框架 API 开发，而不是直接操作协议内部实现。

## 从哪里开始

- 按[框架快速开始](./quick-start.md)开发一个服务。
- 了解 [Application 仓库](https://github.com/neton-application/neton-application)，在选择发行版前检查模块与依赖声明。
- 按需安装[开发技能](https://github.com/netonframework/netonframework.github.io/tree/main/skills)，获得版本相关的实现指导；技能不能替代测试。
